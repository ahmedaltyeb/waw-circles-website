# WEBSITE_TECHNICAL_AUDIT — Waw Circles Technologies FZE LLC

Audit date: 12 October 2026
Scope: local repository only (`website/` + `docs/`). **No live URL was supplied** (the `[INSERT WEBSITE URL]` placeholder was left unfilled), so no deployed site was assessed.
Method: static inspection of source, build output (`website/dist`), documentation, and read-only scripted checks (link/heading/alt scan of `dist`). No source, config or dependencies were modified. The site was **not rendered in a browser**, so visual, contrast and screen-reader results are unverified.

Legend: **[V]** verified from files · **[I]** needs further investigation · **[R]** recommendation.

---

## 1. Executive summary

The project is a **bilingual (Arabic/English, RTL-aware) static marketing site** for a UAE software company, generated by a dependency-free Node script. It is more complete than the documentation suggests: 12 page types × 2 locales (28 HTML files incl. 404s and root), zero broken internal links, one H1 per page, unique titles, all images with alt text, 1.4 MB total, self-hosted fonts, no third-party requests.

It is **not production-ready**. The blockers are not code defects but missing decisions and plumbing:

1. **The contact form delivers nothing.** No endpoint is configured; it only opens the visitor's mail client. [V]
2. **Four named client projects are published without evidence or permission**, contradicting the project's own ground rules. [V]
3. **The default build emits no canonical/hreflang/sitemap/robots**, and there is no deployment config, tests, CI, or version control. [V]
4. **Documentation describes a different system** (Next.js/TypeScript/Tailwind/API route) than the one built. [V]

Recommended next phase: **"Production readiness" hardening**, not new features (Section 8–9).

## 3. Architecture and technology assessment

**Verified stack [V]**
- Node ≥18 ES modules, no runtime dependencies (`website/package.json`).
- `src/build.mjs` (520 lines) renders HTML via template strings; `src/content.mjs` (57 KB) holds all EN/AR copy; `src/art.mjs` generates SVG illustrations; `src/assets/js/main.js` (vanilla JS: menu, slider, video control, form).
- Output: `dist/` (deployable to any static host). `serve.mjs` is a dev-only preview server.
- Optional tooling: `website/tools/` (hero-video generator using `@napi-rs/canvas`, `ffmpeg-static`).

**Assessment**
- Good fit for a brochure site: simple, fast, cheap to host, no attack surface. Keeping this stack is justified; **no change recommended** (the Next.js plan in `docs/ARCHITECTURE.md` is only needed if a server contact route is chosen, and even then a small serverless function beside a static site would suffice).
- Weak points: `build.mjs` mixes layout, SEO, icons and page logic; `content.mjs` is a single 57 KB file with copy and data intermixed; no content validation (the docs' `validate-content` gate does not exist).

## 6. Security, performance, SEO and UX assessment

**Security**
- Attack surface is minimal (static files, no server code, no secrets found in repo; `config.js` contains only the public email). [V]
- Output escaping: build uses `esc()` for interpolated copy; form message JSON is `<`-escaped. No XSS vector found in reviewed paths. [V, limited review]
- No security headers/HTTPS/cookie policy can be assessed without a host (F9). [I]
- Once a form endpoint exists: CORS/origin check, size limit, header-injection rejection, rate limiting, provider key secrecy are required (see `docs/ARCHITECTURE.md` §6, still valid as a spec).

**Performance** [V from sizes; not measured in a browser]
- `dist` 1.4 MB total; hero video 657 KB + 33 KB poster; five woff2 fonts (17–34 KB each), one preloaded. No JS framework; one 9 KB script. Likely strong; Lighthouse/Web Vitals **not run** [I].

**SEO**
- Unique title/description per page, one H1, localized `og:locale`, Organization JSON-LD on home, noindex on 404 — present. Canonical/hreflang/sitemap/robots conditional on `SITE_ORIGIN` (F4).

**UX / accessibility**
- Code-level patterns are good (see Positives). Colour contrast, RTL visual QA, 320–1440 px layouts, 200 % zoom and screen-reader behaviour were **not verified** [I]. Docs claim Gold/Night CTA contrast 9.43:1 (`ARCHITECTURE.md`); not re-measured.

## 10. Testing and acceptance criteria — commands

Run from `website/` (read-only/safe except `build`, which regenerates `dist/`):

```bash
npm run build                                   # expect: "Built 24 pages"
SITE_ORIGIN=https://<domain> npm run build      # then confirm canonical + sitemap.xml + robots.txt exist
grep -rc "rel=\"canonical\"" dist/en dist/ar | head
npm start                                       # preview at http://localhost:4173
curl -I https://<domain>/en/                    # headers (after hosting)
```

Acceptance for launch (summary): all P0 rows above pass; no `publish:true` entry lacking recorded approval; EN/AR enquiry received in the production mailbox; sitemap submitted; accessibility checklist complete.
