# WAW Circles website

Static, bilingual (Arabic / English, RTL aware) site generated by a dependency-free Node script.
Requires Node 20 or newer (`.nvmrc`, `engines`). Only Node 25 has been exercised so far.

## Commands

| Command | What it does | Output |
|---|---|---|
| `npm start` | Default build, then preview at http://localhost:4173 | `dist/` |
| `npm run build` | Default build for local work. No canonical, hreflang, sitemap or robots.txt unless `SITE_ORIGIN` is set | `dist/` |
| `node src/build.mjs --staging` | Private pre-production build: every page `noindex`, no SEO output, marker `<meta name="waw-build" content="staging">` | `dist/` |
| `npm run build:prod` | Production build. Refuses to run unless `SITE_ORIGIN` is a valid public https origin | `dist/` |
| `npm test` | Default build, then the whole test suite | `dist/` |
| `npm run release` | `npm test`, then `build:prod` (fails closed without a valid `SITE_ORIGIN`) | `dist/` |
| `npm run demo` | Design preview with sample partners/testimonials, always `noindex`. Never deploy it | `dist-demo/` |

`--staging` cannot be combined with `--prod` or `--demo`.

## Deploying

1. Upload only the contents of `dist/`, produced by the command that matches the environment:
   production uses `SITE_ORIGIN=https://<confirmed-domain> npm run release`; staging uses `node src/build.mjs --staging`.
2. Never upload `dist-demo/`, the repository, or a staging build to production (a staging build is `noindex`).
3. **Protect staging at the hosting layer** (password, SSO or IP allow-list). `noindex` is a second line of defence:
   it keeps well-behaved crawlers from indexing HTML pages, but it is not access control and does not cover images or video.
   The staging build deliberately writes no `robots.txt` Disallow, so a crawler that is allowed in can read the `noindex`.
4. Host configuration (not in this repository yet): HTTPS only, directory URLs (`/en/about/`) served from `index.html`,
   `404.html` served with a 404 status, long caching for `assets/`, and security headers. The pages contain no inline
   scripts or styles, so a policy such as `default-src 'self'; img-src 'self' data:; media-src 'self'; connect-src 'self' <form endpoint>`
   is a realistic starting point; test it on a preview before enabling.

## Build options (environment variables)

- `SITE_ORIGIN=https://example-domain.tld`: adds canonical, hreflang, `og:url`, `sitemap.xml` and `robots.txt` (default and production builds).
- `CONTACT_ENDPOINT=https://...`: where the contact form POSTs JSON (`name, email, company, interest, message, locale`).
  The endpoint must answer HTTP 2xx with `{"ok": true}` only when the message was accepted. If it is not set, the form
  sends nothing and says so, and offers the company mailbox as a link.

## Pages (each in /en and /ar)

Home, About, Services, Think & Design, Build & Connect, Support & Continuity, Products, How we work, Your next stage,
Contact, Privacy, plus localized 404 pages. `/` redirects to `/ar/` (or the language saved in the browser).
The Projects page and its links exist only while at least one project has `publish: true` in `src/content.mjs`
(currently none; they need owner permission, see `../docs/LAUNCH_BLOCKERS.md` LB-05).

## Editing

- Copy (both languages): `src/content.mjs`. Hide a product with `publish: false`.
- Layout and sections: `src/build.mjs`. Styles: `src/assets/css/style.css`. Behaviour: `src/assets/js/main.js`.
- Images: files in `src/assets/img/` named `about-1`, `about-2`, `prod-sales`, `prod-pharmacy`, `prod-waw`, `slides/slide-1..4`
  replace the built-in illustration for that spot. **The current JPGs are temporary Unsplash stock photos**
  (see `src/assets/img/CREDITS.md`), not WAW work. Replace them before launch.
- Hero video: `src/assets/video/hero.mp4` (an original brand loop). It is not downloaded for visitors who prefer reduced
  motion, use data-saver, or are on a phone-sized viewport; a button lets them start it.
- `tools/` holds optional asset tooling and old one-off patch scripts; it is not part of the build.

## Before going live

Open owner decisions are tracked in `../docs/LAUNCH_BLOCKERS.md`: domain and hosting, an enquiry delivery service,
privacy review, Arabic review, project permissions, product confirmation and real imagery.
